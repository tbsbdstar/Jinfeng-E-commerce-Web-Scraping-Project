# 拼多多（商家后台）交易数据接口

> 本项目 `platforms/pinduoduo.py` 使用。明文接口，替代了早期的字体反爬 OCR 截图方案。

## 1. 接口地址

```
POST https://mms.pinduoduo.com/sydney/api/mallTrade/queryMallTradeList
```

## 2. 请求体（JSON）

```json
{ "queryType": 0, "queryDate": "YYYY-MM-DD" }
```

| 字段 | 值 | 说明 |
|---|---|---|
| `queryType` | `0` | 固定 0 |
| `queryDate` | `YYYY-MM-DD` | 目标日期，横杠分隔，如 `2026-08-06` |

请求头：`content-type: application/json`。

## 3. 调用方式（关键前提）

必须**在已登录的 `mms.pinduoduo.com` 域的页面里**用带 cookie 的 fetch 发起：

```javascript
fetch(API, {
  method: "POST",
  headers: { "content-type": "application/json" },
  body: JSON.stringify({ queryType: 0, queryDate: qd }),
  credentials: "include",
})
```

流程：先 `goto https://mms.pinduoduo.com/sycm/stores_data/operation?dateFlag=0` 建立登录会话，
再在 `page.evaluate` 里 fetch。若页面 URL 含 `login`，说明登录态失效，需重新登录。

## 4. 响应结构与取值

```
success              ← true 表示成功（false 时看 errorMsg）
result
 └ dayList[]          ← 按天的列表，每个元素是一天
      ├ stateDate     ← 日期 "YYYY-MM-DD"
      ├ payOrdrAmt    ← 支付金额（销售）
      ├ sucRfOrdrAmt1d← 成功退款金额（退款）
      └ payOrdrCnt    ← 支付订单数（订单）
```

取值：在 `dayList` 里按 `stateDate == 目标日` 找到那一天的元素。

## 5. 字段映射

| 业务含义 | 接口字段 | 类型 |
|---|---|---|
| 销售（支付金额）| `payOrdrAmt` | 元，直接用 `float` |
| 退款（成功退款金额）| `sucRfOrdrAmt1d` | 元，直接用 `float` |
| 订单（支付订单数）| `payOrdrCnt` | 个，`int` |

> 拼多多接口金额单位就是**元**，无需 ÷100（与抖音不同）。

## 6. 时间段（多天）说明

- **接口天生返回一个 `dayList` 列表**（一次调用含多天），这正是它适合按天入库的原因。
- 本项目按天存储，取时间段时**逐天循环调用**（每天 `queryDate` 传当天），从 `dayList` 里精确挑出 `stateDate == 当天` 那条，避免多天数据混淆。
- 实测 7/27 ~ 8/6（今日 8/11，回溯 15 天）均可正常取到。

## 7. 备注

- 另一接口 `getMallTradeInfo` 是**加密**的，别用。
- 早期的字体反爬 OCR 方案（`core/ocr.py`）拼多多已不再使用（该模块仍保留，其它场景备用）。

## 8. 示例返回（截取）

```json
{
  "success": true,
  "result": {
    "dayList": [
      { "stateDate": "2026-08-06", "payOrdrAmt": 1234.5, "sucRfOrdrAmt1d": 123.4, "payOrdrCnt": 10 }
    ]
  }
}
```
→ 销售 1234.5，退款 123.4，订单 10。
