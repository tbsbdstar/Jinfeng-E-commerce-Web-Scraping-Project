# 小红书（千帆 ark）经营数据总览接口

> 本项目 `platforms/xiaohongshu.py` 使用。明文接口，替代了早期"自定义日历坐标 + 页面文本抓取"的方案
> （旧方案跨月取不到上个月的日期，接口无此限制）。

## 1. 接口地址

```
POST https://ark.xiaohongshu.com/api/edith/butterfly/data?type=sellerCarrierChannelOverall
```

## 2. 请求体（JSON）

```json
{
  "requestBody": {
    "blockElements": [
      {
        "blockKey": "sellerCarrierChannelOverall",
        "filterMap": {
          "dateType": 0,
          "dateSelectType": "custom",
          "startDate": "2026-08-09",
          "endDate": "2026-08-09",
          "sellerManageType": "all"
        }
      }
    ]
  },
  "type": "sellerCarrierChannelOverall"
}
```

| 字段 | 值 | 说明 |
|---|---|---|
| `dateType` | `0` | 自定义日期时为 0（`3`=近N天预设）|
| `dateSelectType` | `"custom"` | **关键**：自定义区间；单日取 startDate=endDate |
| `startDate` / `endDate` | `YYYY-MM-DD` | 取单日时两者相同，如 `2026-08-09`。**任意历史日均可，跨月无障碍** |
| `sellerManageType` | `"all"` | 全部经营方式 |

请求头：`content-type: application/json`。

> 说明：`blockKey` 可同时传 `sellerCarrierChannelTrend`（按天趋势，`blockType=time_line`）取每日曲线；
> 本项目只需总览单日值，故只传 `sellerCarrierChannelOverall`（`blockType=single_data`）。

## 3. 调用方式（关键前提）

必须**在已登录的 `ark.xiaohongshu.com` 域的页面里**用带 cookie 的 fetch 发起：

```javascript
fetch(url, {
  method: "POST",
  headers: { "content-type": "application/json" },
  body: JSON.stringify(payload),
  credentials: "include",
})
```

流程：先 `goto https://ark.xiaohongshu.com/app-datacenter/overview` 建立登录会话，再在 `page.evaluate` 里 fetch。
若 URL 含 `login` 或 `customer.xiaohongshu`，说明登录态失效。

## 4. 响应结构与取值路径

```
success / code(0)      ← 成功标志
data[0]                ← blockKey=sellerCarrierChannelOverall 的块
 └ data[0]             ← 一个「指标名 -> {value, proportion, ratio}」的对象
      └ <指标名>.value  ← 取 value
```

## 5. 字段映射（本项目取这 3 个）

| 业务含义 | 接口字段 | 说明 |
|---|---|---|
| 支付金额（销售）| `payGmv` | 元，直接用 |
| 退款金额(退款时间)（退款）| `refundPayGmv` | 元，直接用（=`cardRefundPayGmv`+`noteRefundPayGmv`）|
| 支付订单数（订单）| `payPkgCnt` | 个（支付包裹数；本店直发 订单≈包裹，与页面「支付订单数」一致）|

> **退款口径（2026-08-13 改）**：现用「退款金额(退款时间)」= `refundPayGmv`。
> 旧的「退款金额(支付时间)」= `payRefundAmt`（=`cardPayRefundAmt`+`notePayRefundAmt`）。
> 两口径接口都有、页面也都显示；识别锚点：老文本抓取存的 8/9=123.45 正是 `payRefundAmt`(支付时间)，故另一总额 `refundPayGmv`=退款时间。

> **金额单位是「元」**，无需 ÷100（与抖音的「分」不同）。
> 订单字段说明：`payPkgCnt`（包裹数）与 `payGoodsCnt`（商品件数）在本店历史数据里恒等且都等于页面「支付订单数」；
> 选 `payPkgCnt`。注意别用 `payUserNum`（支付买家数，会偏小）。

## 6. 时间段（多天）说明

- 本项目按天存储，取时间段时**逐天循环调用**（每天 startDate=endDate=当天）。
- 若把 `startDate`≠`endDate` 传成区间，总览块返回的是**区间汇总**；如需按天曲线用 `sellerCarrierChannelTrend` 块。
- 实测 7/27 ~ 8/6（含跨月）逐天均正常，11/11 成功。

## 7. 备注

- 其它可用字段：`refundPayGmv`=退款金额(退款时间)、`payUserNum`=支付买家数、`payGoodsCnt`=支付商品件数、
  `cardPayGmv`/`notePayGmv`=商品卡/笔记支付金额 等（同一 data 对象里，取 `.value`）。

## 8. 示例返回（截取，8/9 单日）

```json
{
  "code": 0, "success": true,
  "data": [ { "blockKey": "sellerCarrierChannelOverall", "data": [ {
    "payGmv":       { "value": 1234.56 },
    "payRefundAmt": { "value": 123.45 },
    "payPkgCnt":    { "value": 10 }
  } ] } ]
}
```
→ 销售 1234.56，退款 123.45，订单 10。
