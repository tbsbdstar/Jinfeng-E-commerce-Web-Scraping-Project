# 电商多平台销售数据抓取 · 逻辑规则说明书

> 本文件是整个工具的「口径字典」。所有抓取、统计、汇总、周报都以此为准。
> 最后更新：2026-08-06

---

## 1. 目标与范围

从 **4 个平台**（小红书、抖音、淘宝、拼多多）的商家后台，按天抓取店铺级销售数据，
自动汇总成月度 Excel，并每周生成一句话周报。

- **抓取粒度**：默认抓「前一天」（近 1 日）。也支持指定**任意单日**或**任意日期范围**补抓。
- **统计粒度**：日 → 周 → 月，均由主数据实时计算，**不写死时间**。

---

## 2. 核心字段（每平台每天 3 个数）

| 字段 | 说明 | 备注 |
|---|---|---|
| 销售（支付金额） | 当天成交/支付金额 | 各平台叫法不同，见 §3 |
| 退款（退款金额） | 当天退款金额 | 口径各平台不同，见 §3 |
| 支付订单数 | 当天支付/成交订单数 | |
| **净销售额** | = 销售 − 退款 | **算出来的，不抓**（Excel 里是公式 `=销售-退款`） |

**永远留空**（按要求不填）：扣除仅退款、退货率、增长率。

### 小红书（已验证 ✅）
- 后台：`https://ark.xiaohongshu.com` → 数据中心 → 商品总览
- 时间：右上「近 1 日」= 前一天单日；或「自定义」指定日期
- 取「数据总览」区：**支付金额**、**退款金额(退款时间)**（2026-08-13 由"支付时间"改为"退款时间"）、**支付订单数**
- 自校验：下方商品明细逐行求和 = 顶部总览（跑通时三项完全吻合）

> 4 平台口径已统一（2026-08-07 更新文档）：都在各平台后台「经营/交易概况」抓 3 个店铺级数字，
> 各平台叫法不同但都映射到 销售 / 退款 / 支付订单数。退款口径各平台不同，按后台显示如实抓取、不强行统一。
>
> **取数方式变更（2026-08-13）**：4 平台均已改为**直接调后台明文接口**取数（不再靠页面文本/日历/OCR），
> 具体接口见 `docs/{小红书,抖音,淘宝,拼多多}接口.md`。口径（下表"标准字段↔各平台字段"）不变，仅取数手段变。
> 每平台仍保留"老方法(页面)"作接口失效时的兜底（config.json `crawl_method`：auto 接口优先/失败回退，page 强制老方法）。

| 标准字段 | 小红书 | 抖音 | 淘宝 | 拼多多 |

> ⚠ 主数据里 2026-08-12 及之前的小红书退款仍是旧「支付时间」口径，如需全表统一须重抓这些历史日。

## 4. 时间与「周」的定义 ⭐

- **一周 = 周一 → 周日**（ISO 周）。已核对：2026-07-27 是周一。
- **前一天**：脚本运行日的前一天（例：8/6 运行 → 抓 8/5）。

### 跨月周的处理（本方案最关键的规则）

以「7/27~8/2」这一周为例（含 7 月的 27-31 和 8 月的 1-2）：

| 场景 | 规则 |
|---|---|
| 周「总计」行 | **7 天全算**（27,28,29,30,31,1,2 之和），不管跨不跨月 |
| 7 月文件的「当月汇总」 | 只算归属 7 月的日期（…含 27-31，**不含** 8/1、8/2） |
| 8 月文件的「当月汇总」 | 只算归属 8 月的日期（含 8/1、8/2、…**不含** 7 月部分） |
| 8 月文件的第一个周块 | 是 7/27~8/2，**完整显示 7 天**（所以建 8 月表时要「记忆」7 月末的数据） |

→ 这就是为什么需要**主数据层**（§6）：它记住每一天，跨月周自然拼得出来。

## 5. 输出文件

### 5.1 月度汇总表
- 命名：`2026年08月各平台销售汇总.xlsx`（按月一个文件）
- 若定时运行时该月文件还不存在，**自动创建**（套用下述结构）。
- 结构（沿用现有模板）：
  - Sheet「各平台销售汇总」：宽表。4 个指标（销售/退款/净销售额/支付订单数），
    每个指标下按 **淘宝 / 抖音 / 拼多多 / 小红书 / 总计** 5 列。
    「总计」列 = 4 平台之和。
  - Sheet「小红书」「抖音」「淘宝」「拼多多」：每平台一张窄表，
    列＝日期 / 销售 / 退款 / 净销售额(公式) / 支付订单数。
  - 行按周分块：每周 7 个日期行 + 总计 + 扣除仅退款 + 退货率 + 增长率（后三者留空）。
  - 月末：当月汇总。
- **金额显示规则（2026-08-13）**：单元格**显示为整数**（数字格式 `#,##0`），但**存储的仍是完整精度值**——
  在 Excel 里点中某个方格时，公式栏会显示真实的精确数字（精确到小数）。订单数本就是整数。

### 5.2 周报
- 命名：`周报_2026-W32_0803-0809.md`（示例）
- 每周一自动生成「上一整周」的周报，内容一句话，例：
  > 上周全平台营业额 10w，净营业额 8w，平均每天 1.43 万。整体较上周持平，
  > 其中淘宝增长 10%，抖音下降 5%，拼多多下降 8%，小红书下降 12%。
- **第一周没有上周可比 → 不输出对比句**（只给本周数据，或不生成）。
- **实现（2026-08-13）**：内置进抓取流程（非独立工具）。
  - **环比口径 = 净销售额（销售 − 退款）**：整体与各平台的增长/下降 % 都按净额算。
  - 只对**已结束的完整周**（周日 < 今天）生成；**金额显示为整数元**（不带小数点，带千分位）。
  - 两处产出：① 文本文件 `outputs/周报/周报_YYYY-Www_MMDD-MMDD.md`；
    ② 嵌入月表「各平台销售汇总」sheet **最下方**（列出该月所有已结束完整周，各一行）。
  - 跨月周（如 7/27~8/2）会同时出现在 7 月表和 8 月表底部。

### 5.3 企业微信群推送 & 数据核对提醒（2026-08-13）

- **每天抓完自动推送**到企业微信群（群机器人 webhook，配置在 `config.json` 的 `wecom` 块）。
  **金额一律显示整数元**（不带小数点，带千分位）：
  - **日报文字**：当天四平台 销售/退款/净/订单 + 合计；
  - **周报文字**：完整周结束时附上"净额环比"那句；
  - **月表 xlsx**：当月汇总表作为附件。
- **数据核对提醒（雷同告警）**：日报里若某平台**今日的"销售 + 退款"与前一日完全相同**（且非 0），
  自动加一行 `⚠ 数据核对提醒：XX 今日销售和退款与前一日完全相同…请人工核对`。
  用途：兜住"平台当天数据未更新 / 抓取错位取到前一天"这类问题——不自动改数，只提示人工去后台核对。

## 6. 主数据层（唯一真相源）

- 文件：`outputs/daily_master.csv`
- 每行一条：`日期, 平台, 销售, 退款, 支付订单数, 抓取时间`
- 净销售额不存（用时现算）。
- 所有 Excel、周报都从这里读；抓取只往这里**追加/更新**（同一天同一平台重复抓＝覆盖更新）。
- 作用：跨月周拼接、任意日期范围统计、「记忆上月」、断点补抓，全靠它。

## 7. 登录与运行

- **登录态持久化**：每个平台一个独立浏览器档案（`browser_profiles/`），复用本机 Chrome。
  首次需**人工登录一次**（密码不写进脚本，安全）；之后自动复用。
- **登录态会过期**（平台安全机制，几天~几周）。过期时脚本**检测到未登录会提醒**（桌面通知 + `outputs/⚠需要重新登录_平台.txt` 标记文件），不会静默出错。
  - 小红书/抖音/拼多多：双击 `登录.bat`，按菜单选平台，在弹出的浏览器里完成登录。
  - **淘宝**：登录反爬最强、无法脚本化，须双击 `淘宝Chrome.bat` 在真人 Chrome 里过滑块登录一次（登录态持久）。
    抓取时若该调试 Chrome 没开，脚本会**自动拉起**（9222 调试端口），定时基本无人值守。
- **定时（2026-08-13 现状）**：Windows 任务计划程序「电商爬虫_全部平台」每天 **9:00** 抓前一天。
  周报在"某完整周结束的那次抓取"时自动生成，无需单独定时。
- **可配置**：输出目录、运行时间、取数方式（`crawl_method`）、企业微信（`wecom`）等都在 `config.json` 里。
