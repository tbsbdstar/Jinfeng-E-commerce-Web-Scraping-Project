# 常开浏览器爬取 · 使用说明（测试版）

> 目的：用一个**常开的有头 Chrome**登录全部 5 个平台并保持不关，验证"常开是否能减少登录过期"。
> 数据/报表/周报/企业微信推送**全部复用各自现有项目**，写进同一份 outputs、发同一个群。

覆盖平台：**淘宝 / 抖音 / 拼多多 / 小红书**（电商销售数据）＋ **聚水潭**（实发/实退周数据）。

---

## 首次使用（3 步）

1. **双击 `常开登录.bat`** → 打开一个 Chrome，含 5 个标签页：
   淘宝 / 抖音 / 拼多多 / 小红书 / **聚水潭**。
2. **在每个标签页里登录**（淘宝要过滑块；聚水潭账号 `你的聚水潭账号`）。
   登录完 **这个 Chrome 窗口一直开着、别关**。
3. 抓数据（两个工具，按需双击）：

| 双击 | 抓什么 | 菜单 |
|---|---|---|
| `常开抓取.bat` | 4 电商平台的销售/退款/订单 | 1 抓昨天 / 2 某天 / 3 日期范围 |
| `常开抓取-聚水潭.bat` | 聚水潭**实发/实退**（11 产品 × 4 渠道） | 1 抓昨天 / 2 某天 / 3 日期范围 / 4 出上周周报 |

抓完各自自动写表、生周报、推企业微信群。

---

## 日常

- Chrome 保持常开。定时任务每天 **10:00** 自动跑（也可手动双击 `.bat` 抓）。
- 出问题会**自动推企业微信群**叫人处理，见下方「异常报警」。
  （标签页/窗口不小心关了：再双击 `常开登录.bat`，会自动补开缺的标签。）

## 异常报警（自动推群，看到就处理）

三类问题会自动发到企业微信群，**不用天天盯**：

| 群里看到 | 说明 | 怎么处理 |
|---|---|---|
| **登录已过期 / 需要重新登录** | 该平台登录掉了 | 切到常开 Chrome 对应标签页**重新登录**，再用工具选 2 重抓那天 |
| **数据为空**（实发/销售额为 0） | 当天疑似没真正取到数 | 去平台后台核对那天是否真的没有；确实取错就选 2 重抓 |
| **与前一天数据完全相同** | 疑似页面没刷新、取到旧数据 | 同上，核对后重抓 |

> 说明：判空以「实发/销售额」为准（实退经常整天为 0 属正常，不算异常）。
> 判重复是**全部数值**都和前一天一模一样才报，自然重合概率极低。
> 报警只提醒、**不会改数据**。

## 聚水潭这块的说明

- **和独立版是同一套逻辑、同一份数据**：
  独立版在 `D:\claude workspace1\聚水潭爬虫\运行.bat`，每次自己开一个**无头**浏览器（用它自己的
  `browser_profiles/聚水潭` 登录态，闲置久了容易过期）；
  常开版**不开浏览器**，直接借用常开 Chrome 里那个一直开着的聚水潭标签页的登录态。
- 产出**完全一致**：写同一份主数据 `聚水潭爬虫\outputs\jst_master.csv`、生成同样的周表、
  同样的「本周小结」、推同一个企业微信群。**两者可互为备份、随时切换、混用也不会乱**
  （主数据按 日期+渠道+产品 覆盖写，重复抓同一天只会覆盖不会重复累加）。
- **两套登录态互相独立**：常开 Chrome 里登的聚水潭，跟独立版 `browser_profiles/聚水潭` 是两份。
  所以首次用常开版，要在常开 Chrome 的聚水潭标签页里**再登录一次**。
- 周一会额外出「上周一句话周报」，规则与独立版一致（周表只推一次，不重复）；
  周一还会单发一条**周日单日数据**的纯文字（不带附件），保证「每天发前一天」不断档。
- **群里的文字 = 这次抓的那一天**（2026-08-21 改）：19 号跑就发 18 号那天的数，不再发「周一~当天」的累计；
  Excel 周表附件不变，里面的「本周小结」仍是整周累计。

## 定时任务的两道保护（2026-09-03 加）

**抓前预热**：定时任务会先重启常开 Chrome 拿全新连接（防 CDP 卡死），但重启后 5 个标签页
同时加载后台页面要抢带宽。所以重启后先**逐个平台等数据页出现就绪标志**（实测约 1 分钟）
再开始抓，避免页面没加载好就做登录判定。

**区分「登录失效」和「页面没就绪」**：登录判定不通过时，先看当前页面是不是真的跳到了
登录页（URL 含 login / passport / sso 等）——

| 情况 | 处理 |
|---|---|
| 确实在登录页 | 判定**登录失效**：生成标记文件 + 桌面通知 + 推企业微信群，需人工重登 |
| 不在登录页（加载慢、网络错误） | 判定**页面未就绪**：只记日志、**不推群不建标记**，稍后补抓即可 |

> 起因：2026-09-03 早上定时任务里抖音、拼多多被判成"登录态失效"并推了群，
> 而事后检测五个平台全部已登录、补抓 35 秒全部成功——是重启后页面没就绪导致的误报。
> 同期小红书报的是 `ERR_CONNECTION_RESET`（网络层错误），也不是登录问题。

## 黑窗口为什么不会再"卡住"（2026-09-08）

定时任务会弹一个控制台黑窗口，**这是有意保留的**——能实时看到跑到哪一步、有没有异常。

但 Windows 控制台默认开着「快速编辑」：**鼠标左键在窗口里点一下就进入"选择"模式**
（标题栏会多出「选择」两个字），此时程序下一次打印会被**无限阻塞**，整轮采集停摆，
按 Esc 才恢复。9/8 早上就踩了：淘宝抖音其实都抓完入库了，却卡在打印下一行上停了 3 分半
（进程只用掉 0.9 秒 CPU），不按 Esc 会一直卡到看门狗 30 分钟后强杀。

现在两个脚本启动时会**自己关掉本窗口的快速编辑**（`_disable_quick_edit()`，只改本进程的
控制台模式，不动注册表、不影响你其它的 cmd/PowerShell 窗口）。窗口照旧显示、输出照旧滚动，
**点它不再会冻结**。启动时会打印一行提示确认已生效。

> 代价：这个窗口里想复制文字，要用**右键 → 标记**，不能直接拖选。

另外，每个平台抓到的结果现在**同时写进日志文件**（原先只在窗口里 print、关掉就没了），
所以窗口滚过去或者事后想查，去 `电商销售爬虫\logs\抓取_YYYYMMDD.log` 都能看到。

## 这次测试要观察什么

- **登录能撑几天不掉**：一直开着后，各平台是不是比以前（无头每次开关）过期得慢了。
- 若明显变久、基本不用天天登 → 说明常开方案成立，就不用去对接淘宝官方 API 了。
- 聚水潭原来大约 3~4 天掉一次登录（曾导致 8/16 定时跑空），重点看常开后能撑多久。

### 切换到常开版跑定时（可选，验证稳定后再做）

现有定时任务跑的是独立版。若要改成常开版：

```
schtasks /change /tn "聚水潭爬虫_实发实退" /tr "\"C:\Users\taobs\AppData\Local\Programs\Python\Python312\python.exe\" \"D:\claude workspace1\常开页面爬取工具\常开抓取-聚水潭.py\" --auto"
```

改回独立版把路径换成 `D:\claude workspace1\聚水潭爬虫\run.py` 即可。
