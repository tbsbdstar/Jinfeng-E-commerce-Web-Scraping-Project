# 常开页面爬取工具 · 方案设计

> 状态：**方案记录（未实现）**。现有电商爬虫的爬取逻辑与流程**保留不动**，本方案只改变"浏览器怎么来 + 登录怎么维持"。
> 记录时间：2026-08-17。

---

## 1. 背景与痛点

现在的爬取（电商销售爬虫 [[ecom-sales-crawler]] + 聚水潭 [[jst-shifa-shitui-crawler]]）是**每次抓取临时开一个无头浏览器、抓完就关**。
两次抓取之间（约一天）登录态处于"没人管"的闲置状态，平台的 session 容易过期——**尤其淘宝子账号约 1 天就掉，几乎天天要人工过滑块重登**，很折腾。

## 2. 目标

- 改成 **"常开一个有头浏览器 + 保持登录"**：浏览器一直开着、停在各平台数据页，靠**页面自身的 JS 心跳/令牌刷新把 session 焐热**，从而**大幅减少登录过期频率**。
- **登录超时时能一键登录**（有头浏览器，人工在对应标签页登一下即可）。
- 有一个**可定时 / 可手动重抓**的工具：抓取前先**检测登录**——没登就报错并推企业微信群、等人解决后再抓；登了就按**原有流程**抓数据、汇总、推群。
- **为移交做准备**：目前先在本机测试，后续会**移交到其他电脑**由他人操作，因此必须考虑**一键部署 / 安装**。

> ⚠ 注意：这**不能**保证彻底不用登录——部分是服务端硬过期（如淘宝），浏览器开着也拦不住。效果是"**重登频率大幅下降，但不为零**"；重登时靠推群提醒 + 一键登录工具解决。

## 3. 覆盖平台（5 个）

小红书、抖音、拼多多、淘宝、聚水潭。

## 4. 核心思路（架构）

- **一个常开的有头 Chrome**（带远程调试端口，如 9222，独立 user-data-dir），**登录全部 5 个平台**：
  - 每个平台开一个**标签页**，停在各自的数据页；不同平台是不同域名，cookie 互不干扰，可同时登录。
  - 窗口**保持不关**；页面自身的定时请求会帮着维持登录态。
- **抓取时**：脚本用 CDP（`connect_over_cdp`）连上这个常开 Chrome →
  - 逐平台找到对应标签页 → **检测登录**：
    - **未登录** → 记录 + **推企业微信群"XX 需要重新登录"** → 跳过该平台（不硬抓）。
    - **已登录** → 走**现有的抓取逻辑**（复用各平台 `_crawl_api` 接口取数）→ 写主数据。
  - 全部抓完 → 渲染月表 / 周报 → **推企业微信群**（复用现有推送）。

> 这其实就是把现在**淘宝那套"CDP 连一个真人登录的常开 Chrome"**，扩展到全部 5 个平台。

## 5. 三个组件

### 5.1 登录工具（有头，一键登录）
- 双击启动 → 打开那个常开调试 Chrome（调试端口 + 独立档案）→ 自动打开 5 个平台标签页到各自数据页/登录页。
- **登录超时时**：双击它（或它本就开着）→ 在对应标签页人工登录 / 重登（过验证码/滑块）。
- 保持窗口常开。
- （对应现有 `淘宝Chrome.bat` 的思路，扩展到 5 平台。）

### 5.2 定时 / 重新爬取工具
- CDP 连常开 Chrome，逐平台检测登录 + 抓取（见 §4）。
- 支持：**每天定时**（Windows 任务计划）、**手动指定某天 / 日期范围重抓**。
- 抓完汇总 + 推群。
- **复用现有 `core/runner` 的调度、`master_data`、`excel_render`、`weekly_report`、`wecom`、`notify`。**

### 5.3 登录检测
- 复用各平台现有 `is_logged_in()`。
- 加"负载高误判"的重试（现有电商爬虫已加，沿用）。

### 5.4 聚水潭的接入方式（2026-08-17 已实现）

聚水潭是**独立项目**（`D:\claude workspace1\聚水潭爬虫`），取数方式也和 4 电商平台不同
（不是调接口，而是驱动报表页：逐产品填商品编码 → 生成报表 → 读各渠道实发/实退），
因此**单独一个入口** `常开抓取-聚水潭.py / .bat`，与 4 平台的 `常开抓取.py` 并列。

接入做法（关键：**不复制业务逻辑**）：
- 给聚水潭 `core/runner.crawl_dates()` 加了一个可选参数 **`ctx`（浏览器上下文）**：
  - `ctx=None`（默认）→ 和以前完全一样，自己开无头浏览器跑（独立版不受影响）；
  - `ctx=常开Chrome的上下文` → 不开浏览器，直接用常开 Chrome 的标签页取数，跑完也不关它。
- `常开抓取-聚水潭.py` 只干三件事：CDP 连 9333 → 取 `browser.contexts[0]` → 调 `runner.crawl_dates(..., ctx=ctx)`。
- 因此**周表渲染、本周小结、周一周报、企业微信推送、登录过期推群提醒**全部沿用聚水潭现有逻辑，
  **一份代码两种浏览器来源**，不会出现两套逻辑走偏。

登录检测：沿用聚水潭现有的 `LoginRequired`（报表页被重定向到 `login.aspx` 即判定过期，约 4 秒），
过期时推企业微信群提醒，提示去常开 Chrome 的聚水潭标签页重登。

## 7. 一键部署 / 移交到其他电脑（重点）

**目标**：打包成一个文件夹，拷到新电脑，双击安装脚本即可用；接手人无需懂技术。

要点：
1. **Python 免安装**：内置便携版 Python，或最终打包成 exe，接手电脑不用装 Python。
2. **依赖预置**：playwright + 浏览器内核随包，或安装脚本 `install.bat` 自动装。
3. **Chrome 路径自适应**：自动探测常见安装路径（`Program Files`/`Program Files (x86)`/用户目录），找不到再提示。
4. **路径全部相对**：不写死绝对路径，整个文件夹拷到哪都能跑（现有电商爬虫已是相对路径的写法，沿用）。
5. **配置集中在 `config.json`**：企业微信 webhook、抓取平台、定时时间、输出目录等，换电脑/换群只改这里。
6. **`install.bat` 一键安装**：装依赖 + 注册定时任务 + 建桌面快捷方式（登录工具、抓取工具、配置账号）。
7. **登录档案不迁移**：`browser_profiles` 里的登录 cookie **不随包拷贝**（安全 + 会失效），新电脑**首次要人工登录一次** 5 个平台（用登录工具一键打开登）。
8. **使用说明.md**：给接手人——怎么首次登录、怎么日常/定时、登录超时怎么办、出问题排查、注意事项。
9. **移交清单**：交付时列清"要拷哪些、装什么、首次要做什么"。

## 8. 待定 / 风险

- **常开浏览器负载**：5 个平台标签 + 本机已有的千牛（17+ AliRender 进程）+ AlibabaProtect，同时开着 + 抓取时挤在一起，可能资源紧张（此前出过"负载高误报未登录"，已加重试兜底，需继续观察）。
- **服务端硬过期**：淘宝等仍会周期性掉登录，靠推群提醒 + 一键登录解决，不能全自动。
- **淘宝 AlibabaProtect**：用普通 Chrome、一天一次读，风险低；但仍是真实经营账号，注意别高频。
- **电脑必须常开机、浏览器不能关**：关了/崩了对应平台就抓不到，直到重开。
- **聚水潭是独立项目**：纳入本方案需在它项目里同样接一套（或本工具跨项目引用）。
- **反爬检测**：连真人登录的真浏览器、每天一次低频读，检测风险低于现有无头方式；保持低频、不并发狂刷即可。

## 9. 实施步骤（后续动手时）

1. 搭"常开 Chrome + 5 平台标签页"的登录工具（有头，一键打开/登录）。
2. 抓取工具：CDP 连接 + 逐平台"检测登录→抓/推群报错"，复用现有取数与汇总推送。
3. 定时任务 + 手动重抓入口。
4. 一键部署包（Python 便携/exe + install.bat + config + 使用说明）。
5. 本机测试跑通 → 打包 → 移交演练（在另一台电脑装一次验证）。
