# 聚水潭 实发/实退 周数据爬虫 · 使用说明

按「产品名称」逐组抓取聚水潭各渠道的**实发数量 / 实退数量**，每天抓昨天，自动按自然周（周一~周日）汇总成 Excel。

---

## 一、这个工具做什么

- **实发数量** ← 报表「销售主题分析」，按「发货时间」筛选
- **实退数量** ← 报表「售后主题分析」，按「登记时间」筛选
- 产品分类**完全以 `分类编码` sheet 为准**：读其中的「产品名称 → 商品编码」分组（当前 12 个产品），
  每个产品把它的所有商品编码填进「包含商品」→ 生成报表 → 读各渠道数量。
  **以后你在 `分类编码` 里增删产品或编码，工具自动跟随，无需改代码。**
- 结果写进 `outputs\每周各渠道实发_实退数据_YYYY年第WW周(MMDD-MMDD).xlsx`：
  - `实发数量` sheet：4 渠道 × 7 天网格 + `总计数量` + `实退数量` + `实发数量`(净=总计-实退)
  - `实退数量` sheet：4 渠道 × 7 天网格 + `实退数量`(周合计)
  - `分类编码` sheet：原样保留
  - **没有数据的格子一律写 0，不留空。**

---

## 二、首次使用（3 步）

1. **安装**：双击 `一键安装.bat`（装 Python、依赖、浏览器内核；可重复运行）。
2. **登录**：双击 `登录.bat` → 弹出浏览器 → 手动登录聚水潭
   （账号 `你的聚水潭账号`，密码你自己填；若提示「改密码」或「短信验证」，按提示走完）→
   登录进首页后回到黑窗口按回车。登录态会保存，以后免登录。
3. **抓数据**：双击 `运行.bat` → 选 `1` 抓昨天。抓完 `outputs` 目录里就有当周 Excel。

---

## 三、日常使用

双击 `运行.bat`，菜单：

| 选项 | 作用 |
|---|---|
| 1 | 抓昨天（数据有一天延时，默认就抓昨天） |
| 2 | 抓指定某天（如 `2026-08-10`） |
| 3 | 抓一段日期范围（补历史数据，如 `2026-08-04` 到 `2026-08-10`） |
| 4 | 设为每天定时自动抓（填 `HH:MM`，如 `09:30`；用 Windows 计划任务） |
| 5 | 取消定时 |
| 6 | 生成周报：留空=上周；输入某天=那天所在周（如输 `2026-07-22` 出 7.20-7.26）。**若那周有天没抓过会先自动补抓再出报表** |
| 7 | 测试企业微信群推送（发一条测试消息到群，验证配置） |

设了定时后，每天到点自动抓昨天并更新当周 Excel，抓完弹桌面通知。

**本周小结（每天累计，自动更新）**：每次抓完，都会把「本周一 ~ 已抓最后一天」的累计小结
（按产品名称的净发货套数 + 实退套数）写进该周 Excel「实发数量」sheet 底部的「本周小结」行——
抓第 1 天是当天小结，抓到第 2 天变成前两天累计，……直到第 7 天是整周小结；**后一天覆盖前一天**。
> 这是 **Excel 文件里**的小结口径（保持不变）；**发到群里的文字**是「这次抓的那一天」的单日数据，两者不同，见「三、六」。

**每周一**定时任务不再只抓昨天，而是**把上周整周（周一~周日）重新采集一遍再出周报**
（2026-08-31 起）。原因：日常单次抓取仍会偶发漏记——8/17~8/30 两周事后复核补回 17 套实退、
13 个格子，而同期连续跑完的 8/1~8/16 只漏 1 套，冷启动首查最容易踩中报表渲染未完成。
整周复核约 **7~8 分钟**（7 天 × 产品数 × 实发/实退；11 个产品时实测 154 次 / 7.0 分钟），加出周报约 1 分钟，
周一整体约 8 分钟；10:15 启动约 10:23 推周报，比原来晚约 4 分钟。昨天(周日)本就属于上周，
已包含在内，不再单独抓一次。校验期间不推群，周报统一推一次。

定时任务还会把**上周**完整周报另存一份 `周报_YYYY年第WW周(...).txt` 并弹通知（想手动出用菜单 6；
菜单 6 输入历史某天=出那天所在周，缺的天会先自动补抓）。

## 三、四 增删产品 / 维护分类编码

**产品清单是数据驱动的**——采集抓哪些商品编码、周表有哪些产品列、日报周报列哪些产品，
全部来自模板 `每周各渠道实发_实退数据_模板.xlsx` 的 **`分类编码` sheet**。改它就够，**不用改代码**。

三个入口，改的都是同一张表：

| 入口 | 位置 | 能做什么 |
|---|---|---|
| 可视化工具 | 「产品分类」页 | 增删改、调整顺序（顺序＝周表产品列的先后），最完整 |
| 独立版脚本 | `运行.bat` → 菜单 **8** | 看当前分类、新增一条、打开模板手改 |
| 常开版脚本 | `常开抓取-聚水潭.bat` → 菜单 **5** | 同上 |
| 直接改 Excel | 模板的 `分类编码` sheet | 三列一组：产品名称、订货分类、商品编码 |

几个要点：

- 改完**下次采集起生效**，周表列、日报周报文案自动跟随；
- **同一个商品编码不能归到两个产品下**（会重复计数），工具保存时会拦下来；
- 一个产品可以有多条编码（如熊猫扶手箱 4 条），会自动合并求和；
- **删掉某产品只是以后不再采集，主数据里的历史记录不会被删**；
- 新增产品后想补它的历史数据，用菜单 3（抓日期范围）跑一遍那段日期即可；
- 产品数会等比影响耗时：每天约 `产品数 × 2` 次查询，周一整周校验约 `7 × 产品数 × 2` 次。

## 三、五 后台运行（无感知）

抓取默认**后台无头运行**：不弹浏览器窗口，你可以正常用电脑。运行记录通过两处体现：
- **命令行窗口**里实时打印每组抓取日志（双击 `运行.bat` 时可见）；
- **桌面通知**：抓完 / 出周报时右下角弹通知，并留在通知中心。
- 日志文件 `logs\` 里也有完整记录。

想临时看浏览器实际操作（排查问题）：把 `config.json` 里 `"headless": true` 改成 `false` 即可弹窗。
**登录（登录.bat）始终有头**——必须让你看到并手动登录。

## 三、六 企业微信群推送

已对接群机器人：**每次抓完 / 每次出周报**，都会自动往群里发两条——
1. **文字**：**这次抓的那一天**的数据（按产品名称的净发货 + 实退）。19 号跑就发 18 号那天的数，
   20 号发 19 号，**不再累计**（2026-08-21 改；以前每天发「周一~当天」的累计：17、17-18、17-19…，越到周末越长、还重复）。
   一次抓多天（补抓 / 菜单 3 范围抓）时合并成一个区间，如 `8.1-8.9`；跨周则每周各发一条；
2. **文件**：那一周的 Excel 周表（群成员可直接下载）——**文件完全没变**，里面的「本周小结」仍是整周累计。

**周一**收到两条消息：先是**周日那天**的单日数据（纯文字、不带附件），再是**上周周报**（整周文字 + 周表 Excel）。
这样既不会收到两份一样的 Excel，「每天发前一天」也不断档。

一天发多次没问题（定时那次 + 你手动跑的那次各发各的；企业微信限制是 20 条/分钟，远够用）。
群里那份 Excel 是 `outputs\` 里那份的**副本**，不会因为推送在 `outputs\` 多出文件。

配置在 `config.json` 的 `wecom` 块：
```
"wecom": { "enabled": true, "webhook": "群机器人地址", "send_text": true, "send_file": true }
```
- 想暂停推送：`enabled` 改 `false`；只发文字不发附件：`send_file` 改 `false`。
- 换群/换机器人：把新的 Webhook 地址填进 `webhook`。
- 验证是否配好：`运行.bat` → 菜单 **7**（发一条测试消息到群）。
- 推送失败只记日志，**不影响抓取**。

## 四、注意事项

- **抓取时别开着当周的 Excel**：被占用会另存成 `..._请关闭原文件后替换_HHMMSS.xlsx`。
- **登录过期**了（抓取报错「报表打不开，可能未登录」/ 桌面通知提示）就再双击一次 `登录.bat`。
- **数据一天延时**：聚水潭报表当天数据次日才全，所以固定抓「昨天」。
- 定时任务要生效，需保证到点时电脑开机、且聚水潭登录态未过期。

## 六、数据口径

- 周 = 周一~周日。跨月不影响（周表按整周展示）。
- `实发数量` sheet 底部：`总计数量`=网格求和；`实退数量`=引用 `实退数量` sheet 周合计；`实发数量`=总计-实退。
- 渠道按报表「渠道」列前缀匹配（如报表「小红书-劲风车生活的店」归入「小红书」），同一渠道多行（售后按退货类型拆分）自动求和。
